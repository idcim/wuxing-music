# 小程序端（weapp）待办清单

> **为什么单独一份**：服务器上的 1Panel 计划任务只重建 **后端 / 后台 / H5** 三个容器，
> 小程序包必须**手工 `build:weapp` → 开发者工具上传 → 提审 → 发布**。
> 于是小程序的欠账会**独立累积**，而且不会被任何一次 `git push` 清掉——
> 这份清单就是那本账。**每次发版后回来勾一遍。**
>
> 相关文档：部署与域名 → [`DEPLOY.md`](DEPLOY.md) ｜ 版本与安全 → [`ROADMAP.md`](ROADMAP.md) ｜ 规范与陷阱 → [`../CLAUDE.md`](../CLAUDE.md)

> ## 📌 当前决策（2026-08-04，2026-08-08 重申）：**这份账可以一直挂着**
>
> 短期内不上小程序，精力集中在 H5 + 后端 + 后台（推 `master` 即自动部署）。
> 所以下面的 🔴 是「**真去传包时的必办项**」，不是「**现在的阻塞项**」——
> 交付其他功能时不必把重传列为前置条件，记到这里即可。
>
> **但功能可用性的连带影响仍要主动讲**，最典型的一条见第一节末尾的「代理归因」。
>
> **一个例外（v1.7.0 起）**：合规文案的欠账挂着没问题，
> 但**一旦要提审或被平台抽查，它就从欠账变成阻塞**——线上包里的测评题
> 仍在问「您身体哪方面最需要调理？」。所以「一直挂着」的前提是**一直不提审**；
> 哪天要动小程序，第一步是传包而不是提审。

**⚠️ 线上小程序包的实际版本尚未确认**（`version.json` 里记为 `published: unconfirmed`）。
仓库源码已到 v1.8.0；若线上包早于 v1.2.0，则下面第一节的不兼容问题**已经在线上发生**。
上传发布后请把实际版本回填到 `version.json` 的 `channels.weapp.published`。

## 一、🔴 传包时必办：重新构建并上传小程序包

后端已经推进到 v1.8.0，而小程序包只有手工上传才会跟上。
**这不只是"少了新功能"，是可能已经有接口对不上了**：

- [ ] **`bind-phone` 已不兼容**（v1.2.0 起）。`POST /api/mp/bind-phone` 现在强制校验
      `scene=bind` 的短信验证码，而 v1.2.0 之前的包**不带 `code`**，后端一律回 400「请输入验证码」。
      → **若线上包早于 v1.2.0，小程序的"绑定手机号"现在就是坏的**（先去确认线上包版本）。
- [ ] **线上包版本之后的功能都还没上去**。按线上包实际版本对照
      [`ROADMAP.md`](ROADMAP.md) 的变更记录，大致是：手机号/密码登录（v1.1）、
      个人信息可编辑与加载失败重试态、试听到点断流、支付失败原因透传（v1.2）、
      生日与本命五行（v1.3）、代理中心与推广码归因（v1.4）、代理中心的下级视图（v1.5）、
      分成改加法模型后的代理中心文案（v1.6）、五行文案合规改造（v1.7）、
      主路径五音内容与「五音对照」页（v1.8）。
- [ ] **v1.8.0 的界面改动一件也没上小程序**：首页「今夜之音」、探律的讲法与关键词、
      新页 `pages/tones/index`（`app.config.ts` 新增了页面注册，**只有重新构建才会生成**）、
      播放器按曲目元素取配色。这些全在包里，接口一个都救不回来。
      小程序侧目前仍是「火型 · 徵音」加一排曲目 —— 也就是本次要解决的那个问题在小程序上原样存在。
- [ ] **代理中心文案与旧包不一致**（v1.6.0）。分成规则从「上级抽下级的」改成
      「上级加成由平台额外出」，后端出参同步变了：`/agent/me` 去掉 `upline`、
      `/agent/commissions` 去掉 `baseAmount`，且 level=2 行的 `rate` 现在是**订单额**的比例。
      旧包读到 `undefined` 只会静默隐藏那两块说明（不会报错），但**「下级抽成」这个标签
      和它旁边的百分比仍按旧口径显示**——代理会看到一个对不上账的说法。重传即修复。
- [ ] **合规文案只改到一半**（v1.7.0）。五行文案（`desc` / `sleepTip`）走
      `/api/mp/elements`，`stores/content.ts` 的 `hydrate()` 会把结果回写进 `WUXING`，
      所以**旧包也能自动拿到新的合规文案**——这部分不用传包。
      但下面这些是**编进包里的常量**，不传包就一直是旧的：
      （v1.8.0 补充：曲目 tag 也走接口，`舒肝解郁 / 清热宁神` 等 5 个已由
      `_migrate_track_tags` 在服务端换掉，**旧包同样自动生效**，不用为它传包。）
      - 测评题库（`constants/quiz.ts`）：线上仍在问
        **「您身体哪方面最需要调理？肝胆 · 眼睛 · 筋骨紧张」** —— 这是本次要清掉的
        问诊式题干，也是最容易被判为养生医疗的一处。
      - 引导页 `BASED ON TRADITIONAL CHINESE MEDICINE` / 「通过中医五行体质测评」。
      - 结果页卡片标题 `Healing Direction`、各页分享语「按中医五行体质匹配专属安神助眠音律」。
      - 关于页与结果页的常驻免责声明（新加的，旧包没有）。

      → **一旦要提审或被平台抽查，这条就从"欠账"变成"阻断"**。
      提审前必须先传包，否则等于拿着旧的医疗口吻文案去过审。
- [ ] 上传流程：`npm run build:weapp` → 微信开发者工具打开 `dist/` → 上传 → 后台提审 → 发布。
      发布后把实际版本回填到 `version.json` 的 `channels.weapp.published`。

### ⚠️ 不传包的实际后果：代理归因只剩 H5 一条路

这是「不传包」影响**当前可用功能**的一条，不能跟上面那些"少了新功能"混为一谈。

推广码有两个入口，采集逻辑 `captureAgentCode()`（`src/services/agent.ts`，v1.4 才加）
**只在新包里有**。所以只要包不传：

- ❌ **实体店贴小程序码 = 完全不归因**。顾客扫码进小程序、下单、付款一路正常，
  但 `user.agent_id` 始终为空 → `record_commission` 直接 return，**一条分成记录都不产生**。
  店家会以为系统坏了，而后台什么也查不到（模块的设计就是关/不匹配时不留痕迹）。
- ✅ **网络推手分享 H5 链接（`?a=xxx`）正常**——后端与 H5 都已随自动部署上线。

**开启代理分成时的规避办法**：先只谈网络推手；若要签实体店，给他们
**普通链接二维码**（`POST /api/mp/qrcode/url`，指向 H5）而不是小程序码
（`POST /api/mp/qrcode`）。等哪天真传包了，这条限制自然消失。

> 提示：提审前先用**体验版**把下面第三节的真机验证跑一遍，别等审核过了才发现问题。

## 三、🟠 待真机验证（本地和 H5 都验不了）

以下都是**只写了代码、没在小程序真机上跑过**的路径。模拟器不可信（`CLAUDE.md` 陷阱 7）：

- [ ] **推广海报改用 Canvas 2D**（v1.5.1）。`<Canvas type="2d">` + `createSelectorQuery`
      取节点这条路**本地测不了**，H5 端已用无头浏览器出图逐张看过版式，
      小程序端需 `build:weapp` 后用开发者工具真机预览一次：
      确认海报能生成、字号层次正常、二维码清晰可扫、保存到相册可用。
      若节点取不到会 toast「海报生成失败」，日志里是 `CANVAS_NOT_READY`。
- [ ] **`<Picker>` 生日 / 出生时辰**（v1.3.0 新增，**全仓首次使用 `<Picker>`**）。
      H5 端已验证渲染、弹出与传参正确，但**点"确定"触发 `onChange` 那一步没能在本地验证**
      （合成事件打不进去，Taro 绑的是真实 touch 事件）。小程序端需完整点一次：
      选中 → 确定 → 值回写 → 本命五行那行出现。
      兜底方案：若 Picker 在小程序端表现异常，退回自绘抽屉（参照 `SleepTimer`，其内无 `<Input>` 可安全条件渲染）。
- [ ] **试听到点是否真正断流**。H5 端靠清 `src` 已验证；小程序端 `release()` 调的是
      `BackgroundAudioManager.stop()`（`src/services/audio/index.weapp.ts:62-66`），
      注释断言它会终止音源加载，**但没在真机上量过**。
      验证方法：非会员试听一首大文件，30 秒到点后看流量是否停止增长——
      若仍在下载，几百 MB 的 WAV 会把用户流量吃光。
- [ ] **大文件 WAV 的 Range / seek 表现**。`BackgroundAudioManager` 原生发 `Range` 请求，
      链路理论上通的，但数百 MB 的 WAV 在真机上首次加载耗时、拖动进度条、锁屏恢复
      这几项都没实测过。弱网 iOS 尤其要看（`CLAUDE.md` 陷阱 7）。
- [ ] **个人信息编辑抽屉 `UserEditSheet`**（v1.2.0 新增）。设计时主要针对 H5 的
      `<Input>` 陷阱（陷阱 14），小程序端 `<Input>` 行为不同，需确认昵称/手机号/密码三个形态切换正常。
- [ ] **`code → openid`**。配上真实 AppSecret 后要确认走的是 `jscode2session` 换来的真 openid，
      而不是游客兜底（`CLAUDE.md` 陷阱 5）。**验证点：换台设备登录，用户身份不应漂移。**

## 四、🟠 功能缺口：微信原生能力没接

小程序有、但项目里没用上的能力。都不阻断上线，但直接影响转化和体验：

- [ ] **一键获取手机号**（`<Button open-type="getPhoneNumber">`）。
      现在小程序端绑手机号也得走"填号码 → 等短信 → 填验证码"，
      而微信原生一次授权即可。全仓无 `getPhoneNumber`（已确认）。
- [ ] **客服会话**（`<Button open-type="contact">`）。
      后台「小程序配置」里有 `customer_service` 字段可填（`admin/src/views/MpPanel.vue:21`），
      但**前端没有任何地方消费它**——填了等于没填。同样情况的还有 `original_id`。
- [ ] **订阅消息 / 睡眠提醒推送**。`requestSubscribeMessage` 全仓零使用（已确认），
      Phase 3 里这项一直挂着未做。需要：申请模板 → 前端授权 → 后端定时下发。
- [ ] **小程序端登录方式单一**。weapp 分支只渲染"微信一键登录"（`src/pages/login/index.tsx:147-162`）。
      后果：**在 H5 用手机号注册的用户，到小程序端登不进同一个账号**（除非开放平台 UnionID 打通）。
      要么补手机号登录入口，要么确保 UnionID 生效。
