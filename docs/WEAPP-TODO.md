# 小程序端（weapp）待办清单

## 一、🔴 必办：重新构建并上传小程序包

后端已经推进到 v1.3.0，而小程序包只有手工上传才会跟上。
**这不只是"少了新功能"，是可能已经有接口对不上了**：

- [ ] **`bind-phone` 已不兼容**（v1.2.0 起）。`POST /api/mp/bind-phone` 现在强制校验
      `scene=bind` 的短信验证码，而 v1.2.0 之前的包**不带 `code`**，后端一律回 400「请输入验证码」。
      → **若线上包早于 v1.2.0，小程序的"绑定手机号"现在就是坏的**（先去确认线上包版本）。
- [ ] **线上包版本之后的功能都还没上去**。按线上包实际版本对照
      [`ROADMAP.md`](ROADMAP.md) 的变更记录，大致是：手机号/密码登录（v1.1）、
      个人信息可编辑与加载失败重试态、试听到点断流、支付失败原因透传（v1.2）、
      生日与本命五行（v1.3）、代理中心与推广码归因（v1.4）。
- [ ] **代理分成依赖重传才完整**（v1.4）。后端与 H5 随自动部署已生效，但小程序端：
      ① 代理看不到「代理中心」；② **扫小程序码带的推广码不会被采集**
      （`captureAgentCode` 在新包里才有），实体店贴的小程序码归因直接失效。
      开启代理分成前务必先把小程序包传上去，否则线下渠道的单子全部算不到代理头上。
- [ ] 上传流程：`npm run build:weapp` → 微信开发者工具打开 `dist/` → 上传 → 后台提审 → 发布。
      发布后把实际版本回填到 `version.json` 的 `channels.weapp.published`。

> 提示：提审前先用**体验版**把下面第三节的真机验证跑一遍，别等审核过了才发现问题。

## 二、🔴 微信平台后台配置（不在代码里，最容易漏）

这几项配在微信后台，代码里改不了，也无法在本地验证：

- [ ] **request 合法域名** = `https://app-api.azure-glow.cn`
      （`src/constants/env.ts:7`——**H5 走同源反代不需要，只有小程序端用这个绝对地址**）。
- [ ] **downloadFile 合法域名** = 后端域名 **+ 音频 OSS / CDN 域名**。
      v1.2.0 起大文件音频可能直传到 OSS，域名和后端不同；漏配的表现是
      **真机放不了音频，模拟器却正常**（模拟器不校验域名）。
- [ ] **主体备案**：小程序需完成备案才能发布。
- [ ] 若启用微信支付：商户号需绑定该小程序 AppID。

## 三、🟠 待真机验证（本地和 H5 都验不了）

以下都是**只写了代码、没在小程序真机上跑过**的路径。模拟器不可信（`CLAUDE.md` 陷阱 7）：

- [ ] **`<Picker>` 生日 / 出生时辰**（v1.3.0 新增，**全仓首次使用 `<Picker>`**）。
      H5 端已验证渲染、弹出与传参正确，但**点"确定"触发 `onChange` 那一步没能在本地验证**
      （合成事件打不进去，Taro 绑的是真实 touch 事件）。小程序端需完整点一次：
      选中 → 确定 → 值回写 → 本命五行那行出现。
      兜底方案：若 Picker 在小程序端表现异常，退回自绘抽屉（参照 `SleepTimer`，其内无 `<Input>` 可安全条件渲染）。
- [ ] **试听到点是否真正断流**。H5 端靠清 `src` 已验证；小程序端 `release()` 调的是
      `BackgroundAudioManager.stop()`（`src/services/audio/index.weapp.ts:62-66`），
      注释断言它会终止音源加载，**但没在真机上量过**。
      验证方法：非会员试听一首大文件，30 秒到点后看流量是否停止增长——
      若仍在下载，几百 MB 的 WAV 会把用户流量吃光。
- [ ] **大文件 WAV 的 Range / seek 表现**。`BackgroundAudioManager` 原生发 `Range` 请求，
      链路理论上通的，但数百 MB 的 WAV 在真机上首次加载耗时、拖动进度条、锁屏恢复
      这几项都没实测过。弱网 iOS 尤其要看（`CLAUDE.md` 陷阱 7）。
- [ ] **个人信息编辑抽屉 `UserEditSheet`**（v1.2.0 新增）。设计时主要针对 H5 的
      `<Input>` 陷阱（陷阱 14），小程序端 `<Input>` 行为不同，需确认昵称/手机号/密码三个形态切换正常。
- [ ] **`code → openid`**。配上真实 AppSecret 后要确认走的是 `jscode2session` 换来的真 openid，
      而不是游客兜底（`CLAUDE.md` 陷阱 5）。**验证点：换台设备登录，用户身份不应漂移。**

## 四、🟠 功能缺口：微信原生能力没接

小程序有、但项目里没用上的能力。都不阻断上线，但直接影响转化和体验：

- [ ] **一键获取手机号**（`<Button open-type="getPhoneNumber">`）。
      现在小程序端绑手机号也得走"填号码 → 等短信 → 填验证码"，
      而微信原生一次授权即可。全仓无 `getPhoneNumber`（已确认）。
- [ ] **客服会话**（`<Button open-type="contact">`）。
      后台「小程序配置」里有 `customer_service` 字段可填（`admin/src/views/MpPanel.vue:21`），
      但**前端没有任何地方消费它**——填了等于没填。同样情况的还有 `original_id`。
- [ ] **订阅消息 / 睡眠提醒推送**。`requestSubscribeMessage` 全仓零使用（已确认），
      Phase 3 里这项一直挂着未做。需要：申请模板 → 前端授权 → 后端定时下发。
- [ ] **小程序端登录方式单一**。weapp 分支只渲染"微信一键登录"（`src/pages/login/index.tsx:147-162`）。
      后果：**在 H5 用手机号注册的用户，到小程序端登不进同一个账号**（除非开放平台 UnionID 打通）。
      要么补手机号登录入口，要么确保 UnionID 生效。

## 五、🟠 埋好了但没接通的配置

- [ ] **小程序码的 `env_version` 配置不生效**。后台可选 release / trial / develop
      （`admin/src/views/MpPanel.vue:24`），但后端 `mp_qrcode` **硬编码了 `"release"`**
      （`backend/app/routers/mp.py:1417`）。
      后果：**小程序发布前，生成的海报二维码扫出来会提示"该小程序未发布"**，
      开发/体验阶段完全没法测分享链路。改法：把该字段透传进去。
