## 当前媒体策略（2026-10-26 用户调整）

音乐与课程媒体仅原样上传 OSS，暂停全部自动转码，不生成 16-bit、AAC、试听或课程播放副本。课程完成接口仅检查 OSS 文件大小和私有 ACL，记录时长后直接就绪；播放使用原对象的短时签名地址，不下载文件，不调用 ffmpeg/ffprobe，也不新增媒体任务。时长由后台浏览器本地读取或运营填写。新视频使用可直接播放的 MP4，音频使用 MP3/M4A/WAV。已有播放件和试听文件保留。旧课程排队任务只收尾并保留历史，可在后台确认时长后选择“使用原文件”；此操作撤销旧任务租约，避免迟到转码结果覆盖。支付、退款、发货补查继续独立执行。

## 后台渠道配置与加载自检

后台“课程商城运营配置 → 支付、课件与发货配置”维护 2.0 回调域名、微信支付平台公钥、课程数字支付、私有课程桶及发货标记；快递100仍在同页独立维护。现有音乐套餐已经走通的商户号、APIv3 密钥、商户证书和小程序身份继续复用原设置中心，公共 API 地址默认从已配置的音乐支付回调域名推导。课程存储可复用“存储设置”中的 OSS Endpoint 与 AccessKey，但必须填写与公开音乐桶不同的私有课程桶；如果使用独立账号，可在课程商城配置覆盖 Endpoint 和整对 AccessKey。私有桶 ACL 仍在上传和播放时校验。课程数字支付仍使用小程序获准的独立数字内容支付链路。

只有 `commerce:settings` 权限可读取和保存渠道配置。凭证使用服务器现有 JWT_SECRET 派生密钥加密落库，不回显明文；空值保留原凭证，可显式勾选清除。乐观版本冲突返回 409，审计只记录修改字段名称。后台保存优先于旧环境配置，API、通知回调与 Worker 每次按数据库读取，无需重启；解密失败时能力关闭，并提供重新填写修复入口，不回退到旧环境密钥。备份恢复应同时保留原 JWT_SECRET；轮换后需在后台重新填写凭证。已有课件禁止直接更换桶或 Endpoint，已有数字订单禁止直接更换 Offer ID，避免历史业务失效。数据库连接、JWT 根密钥和私有凭证文件目录仍属于服务器基础配置。

“配置加载自检”列出本次请求实际读取的配置项名称、来源和状态；不返回凭证内容、不调用外部渠道。缺项默认展开，保存渠道配置后自检和能力状态自动刷新。“参数已加载”不替代已有渠道真单验收；保存参数也不会自动开放展示或售卖。上传继续检查真实桶 ACL、对象版本及大小，仅原文件上传，不转码。

2026-10-26 迁移到后台渠道配置前，线上公开能力显示：`logistics:true`；`physical_payment`、`course_payment`、`course_ios`、`private_media`、`shipping` 均为 `false`，课程和商城展示／售卖开关均关闭。已从后台自检确认：旧商户和小程序配置存在，缺失的是独立 2.0 参数。按用户要求新增后台维护入口后，由运营在本页补充相应参数；公开能力状态只说明当前请求的配置判定结果，不推翻用户此前的真单验收结论。

## 当前物流方案（2026-10-26 用户确认）

采用快递100实时查询，查询入口及轨迹页位于商城分包，移除微信物流插件声明及调用；微信支付要求的发货上报和收货核对继续执行。在“管理后台 → 课程商城运营配置 → 快递100物流查询”填写服务商提供的 Customer 和 Key，保存后立即生效，无需修改本地文件或重启服务。账号与密钥加密保存在服务器，读取时只返回是否已设置，留空保存保留原值；后台配置优先，关闭后不会回退到环境中的旧账号。附加快递编码映射在上方“实物发货”分组维护，通常保留空 JSON 对象；旧 `COMMERCE_LOGISTICS_*` 环境变量继续兼容。仅有 `commerce:settings` 权限的管理员可管理账号；配置独立保存，防止运费和海报表单覆盖密钥，并拒绝过期页面覆盖新配置。即使课程商城尚未初始化，也可先保存物流账号，修改记录持久保存且不含明文凭证；加密依赖服务器现有 JWT_SECRET，备份恢复需保持该密钥，轮换后可在后台重新填写。需自备已开通实时查询的服务商账号，本轮没有开通付费账号或发生真实查询费用。

服务端先校验登录和订单归属，再使用订单发货快照查询固定 HTTPS 地址。只发送快递公司、运单号及顺丰/中通等必要的收件电话，不发送 openid、完整地址或金额。正式启用前在隐私说明中披露相应物流服务的数据处理。签名按官方要求计算，响应核对公司和运单后只保存标准化轨迹；失败不保存第三方原始异常或响应，也不伪造揽收、运输或签收。

缓存、领取标识与限频保存于 `commerce_logistics_query`：账号至少每秒一次，同一运单跨订单至少间隔 30 分钟，轨迹按发货记录隔离，不向其他收件人的订单共享。网络请求前提交领取，进程中断后保留冷却；签名失败、额度不足或无结果也不立即循环重查。查询失败保留上次结果并标明异常；改运单后清空不匹配缓存，旧领取不能覆盖新结果。快递100签收仅为物流状态，不能自动触发确认收货。依据：[快递100实时查询文档](https://api.kuaidi100.com/document/5f0ffb5ebc8da837cbd8aefc)。

## 范围与业务规则

- 小程序导航：音乐、课程、商城、会员、我的；课程和商城各有独立展示开关。音乐页保留探律入口，迷你播放器提供播放列表。H5 保留原导航与业务。
- 课程：免费领取、整套独立购买、章节试听、视频/音频学习、进度与权益有效期、退款撤权。音乐会员价格与权益不变，不包含课程，不设音乐会员课程价。
- 实物：分类、轮播图、规格库存、购物车、地址、运费报价、多商品订单、支付、人工发货、快递100站内物流查询、微信确认收货、按订单明细退款或退货退款。
- 课程与实物分开下单；购物车只放实物。实物订单统一地址、运费及一个包裹。换货由客服协助重新下单。
- Vben 后台：课程与商品、课程商城交易、课件与任务、课程商城配置。运营可编辑草稿、上下架、海报、内容、售价、章节、规格、库存、配送与售后说明。
- 无直播、线下活动核销、优惠营销、面单、课程会员、离线下载、DRM 或 H5 商城。

管理接口为 `/api/admin/commerce/`。`status` 可在迁移前访问，其余新接口未迁移时返回 503；公开 `config` 会返回关闭状态。现有音乐会员接口和财务表不迁移，统一订单列表聚合历史会员订单，新交易不参与代理分成。

金额使用整数分。创建订单必须提交稳定的 `request_key` 与上次报价 `quoted_fen`；服务端重新计算金额，并拒绝同一幂等键对应不同内容。订单保存标题、规格、价格、课程有效期、支付道具版本、付款身份及地址快照。

后台查询统一返回 `{items,total}`，`page` 从 1 开始，`size` 上限 100。媒体、任务与历史默认每页 20 条，支持翻阅全部记录；不再截断为最近 100 条。媒体按文件名/状态筛选，任务按编号或标识、类型及状态筛选，历史按业务记录、操作人、操作类型筛选，并可用 `subject=job:编号` 精确追踪单个任务。媒体列表不返回课件源文件或播放对象键。

交易列表可组合课程/实物、支付状态与履约状态，按订单号或快递单号查询；售后可按状态、订单号或退款单号查询。失败任务重试使用条件更新，只有一个并发操作能将失败状态改为待处理；审计保存原失败原因与尝试次数，后台可从“处理历史”找回。权限仍由服务端按任务种类校验。

## 交易与异常规则

1. 创建实物订单，通过条件更新预占库存；支付成功后才扣库存。重复支付通知不能重复扣库存或发权益。
2. 待付款订单 30 分钟后关单。未发起支付可直接释放；已发起支付须由渠道确认关闭。预支付请求结果不确定时保留库存，失败任务供人工核对，不能以“查无订单”推定可以释放。
3. 下单、支付、补查、售后和图片上传沿用进程内滑动窗口限流。多实例部署仍需统一限流存储，和现有业务限制一致。
4. 课程权限只认独立权益表。下架课程仍允许合法权益学习；章节目录不返回源文件地址；播放接口校验权益后签发 15 分钟私有地址。播放器启动时暂停音乐，定时及暂停/切章/退出时保存进度。
5. 退款按明细及数量预占可退款数量。拒绝申请释放数量；重复通知只入账一次。未发货商品全部退款后，运费生成独立退款任务，避免部分退款漏退运费。
6. 退货验收由运营决定是否恢复库存；单纯退款不自动回补已发货库存。售后审核、提交退款、恢复库存分别检查权限。
7. 课程退款只撤销该订单来源权益，保留独立来源权益和学习记录。iOS 订单引导 App Store 退款；已验证的渠道主动全额退款也会记录并撤权。

非 iOS 课程申请退款时刷新微信 code，后台绑定原付款身份并加密保存 session_key，仅用于服务端退款用户态签名，不返回客户端、操作日志或列表接口。授权过期后，用户可在订单中刷新授权再重试已批准的退款；不能因此跳过运营审核。

实物退款每次先按原商户退款单号查询渠道。查询成功则校验订单号、交易号、整数分金额及币种，再按结果入账或继续等待；仅明确返回 `404 RESOURCE_NOT_EXISTS` 时才用原退款单号及原金额提交申请。查询超时、其他 404 或服务端错误均保留待核对状态，不推定未受理；`ABNORMAL`、`CLOSED` 等状态保留失败任务供商户平台核查。退款尚未审核通过时，后台任务也不能调用渠道退款。

共享查询地址已按官方规范修正为 `GET /v3/refund/domestic/refunds/{out_refund_no}`，旧音乐会员退款同步仍保持 `NOT_SUBMITTED`、`PROCESSING`、`SUCCESS` 响应约定。申请/查询应答的金额对象必须返回 `CNY`；官方退款通知的金额对象不含币种字段，通知在验签、解密后校验商户、订单、交易号及金额，若额外出现币种字段则拒绝非 `CNY`。依据：[退款查询](https://pay.wechatpay.cn/doc/v3/merchant/4013071041)、[退款结果通知](https://pay.wechatpay.cn/doc/v3/merchant/4013071196)、[官方退款最佳实践](https://pay.wechatpay.cn/doc/v3/merchant/4014959631)。

8. 发货后异步上报微信，失败重试。同步已停止且失败的运单可在后台更正并重试。登记单号不表示已揽收；物流入口由快递100返回轨迹，在订单内展示，不依赖微信物流插件。微信发货和确认收货同步保留。
9. 确认收货调用微信 `weappOrderConfirm` 组件，后端查询平台交易归属、金额和收货状态后才更新本地状态。调用组件成功本身不代表收货成功。
10. APIv3 支付和退款通知先验平台公钥签名再解密；数字通知使用独立的加密消息推送协议并查单验证。前端支付成功不直接开权益。

## 任务与私有存储

任务保存在 `commerce_job`，事件保存在 `commerce_event`，不依赖网页内存。Worker 每次通过条件更新领取任务，使用两小时租约；真正异常最多尝试三次，保留失败原因，可按权限手动重试。等待用户付款、支付结果确认、退款已受理及渠道尚未确认关单属于正常等待，每 60 秒继续补查，不消耗异常重试次数，保留等待历史。尚未发起支付的订单在有效期内也持续保留补查，防止首次检查后用户才付款而丢失自动补偿。新媒体上传完成后直接就绪，不再新增转码任务。

领取任务同时校验计划时间和尝试次数；候选被其他事务延后执行时，不能凭过时查询提前领取。每次执行保存当前次数与租约，支付入账、关单释放库存、退款收尾、媒体发布、发货及收货状态写入前，均在同一事务内锁定任务行并校验归属。租约失效后的旧成功、失败和等待结果不会覆盖接管者状态，另记“过期执行已丢弃”历史。缺失租约的执行中任务也可恢复，错误任务载荷会进入失败历史。租约保护复用现有字段；当前结构版本见下方迁移说明。

旧媒体任务只保留历史并停止转换；确认使用原文件时撤销旧租约，迟到结果无法覆盖。渠道请求可能在租约失效前已被受理，支付和退款继续沿用同一业务幂等编号，通过补查和验真通知确认最终结果。

已就绪的媒体和已同步的发货记录保留完成状态，任务收尾暂时失败不会将它们改回处理中或失败。重试时跳过已完成的上传及发货上报，继续补齐任务结果，避免反复处理已完成的业务。

容器部署将交易任务与媒体任务分为 `commerce-worker`、`commerce-media-worker` 两个进程，媒体队列仅收尾旧任务，新上传不依赖转码。每个进程由独立线程每 15 秒写入心跳；超过 90 秒未更新即视为离线。后台“课件与任务”分别展示两类 Worker 的在线状态，并提示超过计划时间 5 分钟的任务、过期租约及失败总数。统计覆盖全部任务，列表支持分页筛选。心跳仅保留最近 7 天，业务任务和事件历史不随心跳清理。

现有 OSS 已通过实机使用；课程新增的私有课件链路需单独验证。课件必须使用**独立的 private OSS 桶**，上传签名前校验桶 ACL，播放签名前校验对象 ACL。后台直传 OSS，直接以私有原对象供授权播放，不下载、不转换、不生成副本。按新桶和课件域名核对后台域名 CORS、小程序媒体域名、HTTPS 和大文件网络限制。

原文件上传表单及签名条件均固定 `x-oss-forbid-overwrite=true`，每次签发使用独立随机对象键。未启用版本控制的桶由 OSS 拒绝同名覆盖；启用版本控制的桶会忽略该参数，因此上传完成时另从服务端 HEAD 保存 `x-oss-version-id`，ACL 检查和短时播放签名均固定同一 `versionId`，重复完成不切换版本。暂停版本控制产生的可覆盖 `null` 版本拒绝就绪，恢复版本控制后需重新上传；本轮没有转换或复制对象。旧就绪课件缺版本且当前对象已版本化时，播放拒绝静默切换，运营可在后台“确认课件版本”，保留原播放对象、时长及既有衍生文件。课程桶 RAM 权限需允许读取历史版本及其 ACL；生命周期规则不得清理仍被课程引用的版本。依据：[OSS PostObject](https://www.alibabacloud.com/help/en/oss/developer-reference/postobject)、[版本控制](https://www.alibabacloud.com/help/en/oss/user-guide/overview-78/)、[版本 ACL](https://www.alibabacloud.com/help/en/oss/developer-reference/getobjectacl)。

售后图片使用 `COMMERCE_PRIVATE_DIR`，不放公开 `uploads`。限制图片体积/像素、重新编码清除元数据，仅可引用本人的上传记录，读取使用短时签名。目录需持久化、备份并限制宿主机访问。长期留存、孤立上传清理策略在正式运营前需结合售后保留期配置。

## 自动部署顺序

按用户要求，备份、v4 迁移和 Worker 首次启动已纳入部署文件。沿用现有 1Panel 自动部署任务即可，无需另填数据库账号，也不需要管理员逐条执行初始化命令。`docker compose up -d --build` 同样遵守下列依赖顺序：

1. `database-prepare` 使用 `backend/.env` 已有的数据库连接，检查事务备份条件，将 MySQL 客户端配置写入专用临时凭证卷；不输出密码。未支持的连接参数或非 InnoDB 表会停止部署。
2. `database-backup` 用官方 MySQL 8.0 客户端做单库事务快照，包含表、触发器、存储过程和事件，压缩后校验 gzip 并生成 SHA-256。默认文件保存在服务器 `/var/backups/wuxing-music`，目录 700、文件 600，不在站点或 Git 中；可由 `WUXING_BACKUP_DIR` 指定受控路径。备份失败、超时（默认 30 分钟）或写入失败会阻止迁移。请监控备份容量并按运维保留政策归档，脚本不自动删除历史备份。
3. `commerce-init` 必须取得本次备份成功凭据后才执行幂等迁移。当前结构 **v4**；迁移可重复执行，不覆盖运营内容、会员订单或已有展示／售卖设置。首次只录入可编辑草稿，仍须运营审核。
4. 两个独立 Worker 在迁移完成后启动；API 仅在两者均健康后启动，后台和 H5 再启动。`commerce-media-worker` 只收尾旧任务，上传仍直接保存 OSS 原文件，不恢复转码。

临时数据库账号配置在备份结束（含失败）时删除，错误详情仅留在受限凭证卷，部署日志只输出不含账号的结果和备份文件名。数据库备份中的加密物流账号仍需原有 `JWT_SECRET` 才能使用；部署环境配置应按既有运维机制另行保管，不能把密钥贴到聊天或日志中。

Compose 的完成依赖保证服务器仍在执行旧版部署脚本副本时，首次升级也不会绕过备份和迁移。后续 `scripts/auto-deploy.sh` 默认自动纳入版本声明的 Worker，并以成功标记区分“代码已拉取”和“发布已完成”；失败后即使 HEAD 已对齐，下一轮也会重试。`WUXING_COMMERCE=1` 仍兼容；新版本不接受 `0` 跳过必要任务服务，业务开放由后台开关控制。

部署失败时只恢复旧应用容器，跳过初始化依赖链；**不会逆向迁移或自动恢复覆盖生产数据库**。新增结构只向前演进；如需数据恢复，应由运维核对备份并在维护窗口执行。备份失败时新应用不会启动，不能将 API 健康误报为迁移成功。

可用以下只读命令检查结果：

```bash
docker compose ps -a
docker compose logs --tail=60 database-prepare database-backup commerce-init
docker compose exec -T commerce-worker python -m app.commerce.monitor --check
docker compose exec -T commerce-media-worker python -m app.commerce.monitor --check
```

本地独立调试仍可用 `python -m app.commerce.migrate`；这个直接命令不替代部署备份链。正式迁移及真实配置是否生效，须以服务器输出、公开 `commerce_ready` 和后台任务状态为准；本地演练不表示已完成生产操作。新售卖能力没有 `DEBUG=true` 免付兜底，后台能力与素材未核验前保持售卖关闭。
