# APP 管理与发布实施计划

用户要求直接实现后台 APP 配置、OSS 安装包、开放下载页、后台发布更新，以及微信移动应用登录。

## 设计

后台保持两级菜单，在「APP 管理」中分开基础与下载、版本发布、微信登录。安装包沿用已有 OSS 凭证，浏览器直传；服务端重新读取 APK 的包名和版本、计算 SHA256，再允许保存草稿。发布与撤回单独操作，已发布记录不可改写。公开 `/download` 无需登录，仅展示已开放的已发布版本；Android 按实际包名、versionCode 和渠道检查更新，用户确认后在浏览器下载并自行安装。

配置及每份安装包、版本分别使用现有 Setting 独立记录，不变更财务或用户数据，不需要新增数据库表。发布操作锁定 APP 配置记录，序列化同渠道发布；草稿和 OSS 凭证永不公开。APP 微信登录使用移动应用参数，与现有网站扫码参数隔离；AppSecret 仅在服务端使用，配置接口脱敏。登录仍由用户主动勾选协议并发起，可取消、返回游客浏览。

## 任务

- [x] 后端：权限、独立包校验、OSS 直传及完成检查、版本草稿/发布/撤回、公开更新接口与下载页；单元和接口行为验证。
- [x] 后台：三标签 APP 管理，上传进度、真实包信息、版本历史、开放下载地址与微信移动应用参数；后台构建。
- [x] 安卓：更新提示和设置检查入口，微信官方 SDK 登录及取消处理；类型检查、小程序回归、APK 构建。
- [x] 集成：临时库 smoke test、MuMu 页面/更新流程验证、文档，审查后依照已有授权提交推送。真实微信登录需匹配已审核的移动应用 AppID、包名和签名，有微信客户端及获准账号才能完成外部验收。
