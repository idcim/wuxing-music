# 小程序音乐会员与礼物卡虚拟支付迁移

## 目标

小程序内音乐会员、礼物卡新订单只走已获准的虚拟支付；未配置时停止新购。H5 与历史普通微信支付订单继续按原渠道履约、退款。课程与实物订单保持原有独立链路。

## 实施步骤

1. 给套餐增加虚拟商品编号和价格同步标记，给会员订单增加渠道、分价、商品编号、付款 OpenID 和终端快照。使用现有启动加列迁移，存量订单按 `wxpay` 读取。
2. 后台套餐编辑可填写虚拟商品编号并在调价后重新确认价格同步。小程序购买状态按虚拟渠道配置与套餐数据计算，H5 仍使用原售卖开关。
3. 小程序会员和礼物订单以服务端套餐价格建单，核对 `jscode2session` 身份，生成 `requestVirtualPayment` 参数。前端调用虚拟支付并轮询真实订单；生产不可免付。
4. 在现有虚拟支付推送入口分派会员订单，核对支付渠道查单结果、商品编号、金额、数量和 OpenID；幂等地开通会员或发礼物码。支付确认与权益发放同一事务，异步补查覆盖通知延迟。
5. 退款按订单渠道处理。虚拟退款使用渠道能力和退款通知/查单确认，未确认前不撤权；历史普通支付退款不变。
6. 增加后端付款、重复通知、错误金额、礼物、渠道隔离和退款测试；运行后端、前端、后台构建与本地迁移预演。

## 上线门槛

虚拟支付开通、每个在售套餐的虚拟商品及价格同步、推送配置齐备前，小程序新购买保持关闭。真机真实付款与退款仍需在上线环境复核。
